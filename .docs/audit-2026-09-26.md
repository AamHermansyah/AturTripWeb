# Audit keputusan dan sinkronisasi dokumen — 26 September 2026

Audit ini membandingkan [136 keputusan yang disetujui](shared/decisions.md), PRD/TDD/checklist tiga aplikasi, dokumen bersama, serta bukti kode yang relevan. Ini **audit dokumentasi dan status implementasi**, bukan penerimaan fitur produksi.

| Area | Temuan | Sinkronisasi |
| --- | --- | --- |
| Cakupan rilis | PRD web masih menyatakan prioritas MVP belum disepakati secara umum, padahal banyak fitur rilis awal sudah dipilih. | PRD kini menyebut cakupan inti dan fase berikutnya; pertanyaan yang benar-benar terbuka tetap ada pada daftar keputusan. |
| Gambaran produk | Sertifikasi digambarkan sebagai badge bertingkat, data elevasi seolah wajib, dan alur pencairan seolah menunggu ulasan. | Konteks kini mengikuti sertifikasi opsional, elevasi bila tersedia, ulasan tanpa menjadi syarat pencairan, serta persetujuan superadmin. Klaim pasti tentang fitur pesaing dihapus karena belum diverifikasi. |
| Listing | Beberapa instruksi web/API hanya meminta KTP/swafoto sebelum publikasi dan melewatkan review setiap listing baru. | Alur kini membedakan **boleh mengirim untuk review** dari **boleh terbit/dijual**; API memeriksa identitas serta keputusan staf (`D-40`, `D-116`). |
| Pencairan | Permintaan yang menunggu superadmin belum dibedakan jelas dari saldo yang bisa diminta ulang; tiga status grafik pemandu harus tetap utuh. | API memesan saldo saat permintaan dibuat. Kartu saldo menunjukkan jumlah yang masih dapat diminta; grafik historis tetap tiga status dengan subketerangan pencairan diproses (`D-109`, `D-123`). |
| Admin dan analitik | Keputusan antrean admin awal dapat terbaca membatasi analitik pasar yang kemudian disepakati. | `D-119` ditegaskan sebagai **area operasional** dan `D-127` sebagai perluasan analitik; akses staf/superadmin serta sumber event web/API mengikuti spesifikasi admin. |
| Mitra pembayaran | Riset Midtrans berpotensi dibaca sebagai kandidat final, dan gerbang uji payout belum memuat persetujuan superadmin. | Dokumen evaluasi melabeli Midtrans sebagai pembanding, mempertahankan shortlist DOKU/Xendit, serta menambah alur keputusan pencairan. |
| Model API dan ulasan | Daftar model kandidat belum menyebut versi listing, review staf, laporan, ledger, notifikasi, dan analitik. PRD ulasan menyiratkan aturan perubahan telah disepakati. | TDD mencakup domain yang disetujui; kebijakan edit/hapus ulasan dicatat sebagai pertanyaan terbuka. |
| Integrasi browser admin | CORS kerangka API hanya memakai origin default web `localhost:3000`, sedangkan web-admin dikembangkan pada `localhost:3001`. | Kondisi kode dan checklist integrasi mencatat kedua origin perlu diizinkan secara eksplisit; sesi dan izin tetap diverifikasi API. |

## Status yang terbukti di kode

- `apps/web`: 31 route `page.tsx`; mayoritas merupakan UI/data contoh. Dashboard pemandu dan alur operasional belum tersedia.
- `apps/api`: bootstrap Express, `GET /health`, 404, dan error handler; belum ada endpoint domain produk.
- `apps/web-admin`: halaman penanda; belum ada login, dashboard kerja/analitik, review listing, atau operasi keuangan.

Checklist fitur dan integrasi tetap **belum dicentang**. Butir `[x]` yang sudah ada hanya menunjukkan kerangka atau UI awal sesuai teksnya. Keputusan yang masih memerlukan jawaban/uji sebelum peluncuran ada pada bagian **Terbuka** di [decisions.md](shared/decisions.md), terutama mitra/tarif pembayaran, cadangan risiko, retensi data, cakupan saved, serta kebijakan ulasan.
